# fork-updates-r10n — OpenAI и CSAT

## 1. Веха

Выполняет `qw2` в одноразовом клоне. Цель — убрать два исключения AbcSize
без изменения запросов и форматов отчёта. Измерено на `1578624b` в штатном
Docker-образе без наследования todo. `OpenAi::Api#notify_message`
даёт 51.02/30, `Csat::Api#report` даёт 38.5/30. У `AuditsReports`
ноль нарушений, его существующий тест участвует в проверке. Код этих
адаптеров совпадает с измеренным BASE.

## 2. Где работать

Клон `/home/deploy/exec-clones/chaskiq-fork-updates-r10n`.
Спека коммитится в `docs/specs/fork-updates-r10n.md`. База клона — `45cc337f`.
Постановщик проверяет итог после вливания R10m. Работай только в клоне.
git pull в клоне не делать; push в origin запрещён, работу заберёт постановщик через `git fetch` из клона.
Docker под своим UID/GID, установка зависимостей только в контейнере.
Используй существующий `CI_LOCAL_CACHE=$HOME/.cache/chaskiq-r10n-ci`.

## Что проверено вживую

Замер RuboCop описан выше. Чтение методов на BASE подтвердило, что OpenAI
ищет канал перед проверкой части, пишет cache перед HTTP и извлекает id
символьным ключом из распарсенного ответа. CSAT считает долю из
`custom_counts` с `ceil(1)`, фильтрует `plugins.csat` и берёт 10 записей на
страницу. Точные формы результатов исполнитель закрепит на BASE.

## 3. План

1. Добавь `spec/services/message_apis/open_ai_r10n_spec.rb` и
   `spec/services/message_apis/csat_r10n_spec.rb`. Запусти на BASE до кода.
   OpenAI: закрепи отсутствие канала, не-content, human lock и отсутствие
   запроса для уже отправленной или bot-части. С WebMock закрепи запрос
   (URL, метод, Bearer синтетического значения, JSON model/user/messages),
   порядок и роли истории, cache key, объединение текста блоков, запись
   ответа и отсутствие записи при пустом ответе. JSON id читается в
   текущем коде с символом, сохрани наблюдаемое значение.
   CSAT: полная форма general, пустые counts, порядок и округление,
   реальная таблица событий с фильтром и пагинацией, поля meta и columns,
   значения custom и неизвестного пути. Используй существующие фабрики.
   Перед завершением запусти targeted с `outgoing_webhook_spec.rb` первым,
   чтобы обнаружить утечки фоновых задач.
2. Разбей только два измеренных метода приватными помощниками. Для OpenAI
   сохрани порядок ранних выходов, cache write до HTTP и границу rescue
   извлечения ответа. Для CSAT отдели построение general и events_table,
   сохрани фильтр, сериализацию, пагинацию и проценты. На продуктовый коммит
   только два api.rb. Удали из todo ровно строки для OpenAI и CSAT. Сделай
   датированную запись в CHANGELOG. Четыре смысловых коммита, каждый с
   повелительным заголовком до 50 символов. Используй `git commit -F` с
   точной строкой и проверь тело `git log --format=%b`, трейлеры запрещены.
3. Прогони targeted на финальном коде и на копии первого коммита с
   финальными тестами. Прогони штатное CI, source scan и проверь RuboCop без
   todo на обоих файлах. Сохрани логи. Приёмщик повторит CI на текущем main
   после R10m.

## 4. Не трогать

Принимаются два api.rb, две новые спеки, todo и CHANGELOG. Существующие
спеки, SDK, зависимости, конфигурация и Аудиты остаются вне вехи.
Запрещены чтение исходников в спеках, rubocop-директивы и реальные запросы
к провайдерам.

## 5. Критерии приёмки

- **AC-001** — весь сьют RSpec в Docker.
  `bash -c 'CI_LOCAL_CACHE=$HOME/.cache/chaskiq-r10n-ci bin/ci-local --only rspec'`
- **AC-002** — строгий RuboCop.
  `bash -c 'CI_LOCAL_CACHE=$HOME/.cache/chaskiq-r10n-ci bin/ci-local --only rubocop'`
- **AC-003** — спек-тесты проверяют поведение.
  `bash -c 'B=$(git merge-base HEAD @{u}) && python3 -I docs/specs/fork-updates-r10l-probes/source_scan.py "$B"'`
- **AC-004** — пробельная проверка и чистое дерево.
  `bash -c 'B=$(git merge-base HEAD @{u}) && git diff --check "$B"..HEAD && test -z "$(git status --porcelain --untracked-files=all -- . ":(exclude)report.json" ":(exclude)report-blocked.md")"'`

## 6. Авторевью

Запроси agy через `review_run.sh` по коду и спекам. Сохрани квитанцию
или описание недоступности. Дай предложение о поведенческой мутации
одного сценария в каждом адаптере, которую проверит постановщик.

### Контракт отчёта

В корне клона оставь untracked `report.json` с 4 записями в `criteria`.
В каждой `id`, `command` дословно, `status`, `rc` и `note`.
Добавь `executor` с `backend: qwen` и моделью, итоговые SHA и логи BASE,
targeted, измерения без todo и итог ревью.

## 7. Контракт на невыполнимое

При блоке среды сохрани точную ошибку и законченные коммиты. При расхождении
предположений с BASE закрепи фактическое поведение и запиши его в отчёте.
